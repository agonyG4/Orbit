# Freedesktop Icon Theme Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Explorer select installed Freedesktop icon themes strictly and resolve candidate lists theme-first across the complete inheritance family while preserving Qt rendering.

**Architecture:** Add a Qt-only `FreedesktopIconThemeCatalog` that parses `index.theme`, gathers matching theme roots, walks inheritance deterministically, caches direct icon presence, and selects a winning candidate identity. `IconThemeService` keeps selection policy, semantic/MIME candidate generation, rendering, QML URLs, and rendered caching; it delegates only candidate identity selection to the catalog and keeps a final ordinary Qt fallback.

**Tech Stack:** C++17, Qt 6 Core/Gui/Quick/Test, `QSettings` for public INI parsing, `QFileSystemWatcher`, CMake, QtTest.

## Global Constraints

- Qt public APIs only; do not include `qiconloader_p.h` or copy Qt private code.
- Do not add GTK/GIO or an extension-to-icon-name table.
- Keep existing `QMimeDatabase::MatchExtension`, MIME icon names, semantic directory/device names, and symbolic candidate generation.
- Build only in Orbit’s existing `build/debug` tree; do not create a separate temporary build tree.
- Do not use sub-agents.
- Theme policy remains in native C++; provider URLs contain candidate identities, never filesystem paths.

## File Map

- Create `apps/explorer/src/services/freedesktop_icon_theme_catalog.h`: public catalog interface and private metadata/cache declarations.
- Create `apps/explorer/src/services/freedesktop_icon_theme_catalog.cpp`: index parsing, theme-family traversal, direct presence lookup, and watch-path construction.
- Modify `apps/explorer/src/services/icon_theme_service.h`: own the catalog, expose the asset-refresh state internally, and add watcher/topology helpers.
- Modify `apps/explorer/src/services/icon_theme_service.cpp`: replace probe-based existence and candidate-by-candidate Qt lookup, integrate catalog invalidation/watchers, and use DPR-aware Qt rendering.
- Modify `apps/explorer/CMakeLists.txt`: compile the catalog into `astrea_explorer_native_icons`.
- Modify `apps/explorer/tests/cpp/tst_icon_theme_service.cpp`: add deterministic temporary-theme fixtures and catalog/service regression tests.
- Modify `apps/explorer/tests/cpp/tst_icon_image_provider.cpp`: preserve existing provider coverage; no provider production change is required because revision-bearing URLs are generated by `IconThemeService`.
- Modify `apps/explorer/docs/ICON_THEME_INTEGRATION.md`: document catalog ownership, list-aware selection, and asset invalidation.

### Task 2: Implement the Qt-only Freedesktop catalog

**Files:**
- Create: `apps/explorer/src/services/freedesktop_icon_theme_catalog.h`
- Create: `apps/explorer/src/services/freedesktop_icon_theme_catalog.cpp`
- Modify: `apps/explorer/CMakeLists.txt`

**Interfaces:**
- Consumes public `QIcon::themeSearchPaths()`,
  `QIcon::fallbackThemeName()`, `QSettings`, and filesystem APIs.
- Produces the five methods declared in Task 1.

- [ ] **Step 1: Add the minimal catalog declarations and CMake source entries.**

  Define a value-owned, non-`QObject` class with mutable caches. Keep metadata
  private: theme consumers receive only names, selected candidates, and watch
  paths. Add both catalog source files to `astrea_explorer_native_icons`.

- [ ] **Step 2: Implement strict metadata loading.**

  For each valid identifier, inspect `QIcon::themeSearchPaths()` in order for
  `<base>/<theme>/index.theme`. Parse the first readable, error-free INI file
  with an `[Icon Theme]` group containing non-empty `Name`, `Comment`, and
  `Directories` metadata. Include the union of `Directories` and
  `ScaledDirectories`,
  validate relative directory entries, and collect declared `Inherits` in
  order. Keep every matching `<base>/<theme>` directory as an asset root,
  including roots that contribute files without being the metadata source.

- [ ] **Step 3: Implement cycle-safe theme-family traversal.**

  Traverse the selected theme depth-first in declaration order with a visited
  set. Skip missing themes. Defer `hicolor` entries encountered in inherited
  lists until the final themed position. Append the public Qt fallback theme
  and its recursive inheritance after the explicit selected-theme subtree,
  then append installed `hicolor`. Never visit a theme twice.

- [ ] **Step 4: Implement bounded direct icon presence.**

  For each theme/candidate pair, inspect only the metadata-declared relative
  directories across all matching roots and test `.png`, `.svg`, `.xpm`, and
  `.svgz` files. Cache positive and negative results in the catalog and clear
  the metadata/presence caches from `invalidate()`. The cache lifetime is
  bounded by invalidation and the active service family; no recursive theme
  enumeration is allowed.

- [ ] **Step 5: Implement list-aware candidate selection and watch paths.**

  Iterate `themeFamily(themeName)` outermost and the caller’s candidate list
  innermost, returning the first directly present candidate. Build watch paths
  from filesystem-backed search roots, theme directories, `index.theme`, and
  declared icon directories for the requested theme names and their family;
  omit `:/`/resource paths so `QFileSystemWatcher` never receives them.

- [ ] **Step 6: Run the catalog tests and verify the green result.**

  Run:

  ```sh

  rtk ctest --test-dir build/debug -R '^icon_theme_service$' --output-on-failure
  ```

  Expected result: all new catalog tests pass, including cycle, split-root,
  scaled-directory, and final-`hicolor` cases.

  ```sh
  rtk ctest --test-dir build/debug -R '^icon_theme_service$' --output-on-failure
  ```

  Expected result: the new assertions fail because the old service probes Qt
  fallback icons and resolves each candidate through the whole hierarchy.

- [ ] **Step 3: Replace probe-based `themeIsUsable()`.**

  Delegate only to `m_catalog.themeExists(themeName)`. Remove temporary global
  `QIcon::setThemeName()` calls and probe lists. Preserve strict identifier
  validation, exact environment overrides, explicit appearance suffixes, and
  appearance sibling selection.

- [ ] **Step 4: Make `resolveIcon()` select identity before asking Qt to render.**

  Ask the catalog for one winning candidate using `m_effectiveTheme`. If it
  returns a name, call `QIcon::fromTheme()` once for that name. If no themed
  candidate exists, retain the existing per-candidate `QIcon::fromTheme()`
  loop as the final unthemed/platform fallback. Do not change candidate
  construction or symbolic mappings.

- [ ] **Step 5: Use Qt’s DPR-aware pixmap overload without needless resampling.**

  Request the icon at the logical size and bounded DPR with public
  `QIcon::pixmap(const QSize &, qreal, ...)`. Place the returned image into
  the physical result canvas without `QImage::scaled()` when its native size
  already matches; only size-adjust as a defensive mismatch path. Preserve
  alpha, aspect ratio, symbolic artwork, and the existing built-in fallback.

### Task 4: Add live theme-family invalidation

**Interfaces:**
- Consumes `FreedesktopIconThemeCatalog::watchPaths()` and `invalidate()`.
- Produces unchanged-theme asset invalidation through the existing revision,
  `themeChanged`, rendered-cache, and provider-URL mechanisms.

- [ ] **Step 1: Write failing live-change tests.**

  Add a test that renders an icon, replaces the same active-theme asset with a

  debounced watcher, and asserts a higher revision, one `themeChanged` signal,

- [ ] **Step 2: Run the tests and observe stale-cache/selection failures.**

  ```sh
  rtk cmake --build --preset debug --target tst_icon_theme_service
  rtk ctest --test-dir build/debug -R '^icon_theme_service$' --output-on-failure
  ```

  Expected result: the old implementation keeps the same revision/cache and
  does not discover an appearance sibling installed after startup.

- [ ] **Step 3: Track active catalog watch paths and topology signatures.**

  Extend `updateWatcher()` with catalog paths for the effective theme, config
  base, exact environment override, platform theme, and compatibility base
  plus appearance siblings. Keep config watching intact. Store a compact
  existence signature for candidate theme names so top-level search-root
  notifications caused by unrelated theme additions can be ignored.

- [ ] **Step 4: Debounce relevant filesystem changes and refresh safely.**

  On active-family/index/icon-directory events, mark assets dirty, invalidate
  the catalog, and start the existing single-shot timer. On search-root events,
  invalidate temporarily, compare the topology signature, and schedule only
  when relevant theme existence changed. In `reloadConfig()`, reselect the
  effective theme; when assets were dirty and the name is unchanged, clear the
  rendered cache, increment the revision, and emit `themeChanged`. Rebuild
  watch paths after every reload so removed files do not leave stale watches.

  Expected result: unchanged-name asset replacement refreshes rendered URLs and
